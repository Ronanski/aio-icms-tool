# UI/UX, visual quality and functional audit (2026-10-22)

Audited commit: `1cfa84e` on `ccr-85df8617-jwtaxb` (= `main` `6714da6` + the engine audit report). **No application
code was changed.** This report is for approval: nothing below is implemented yet.

Companion report: [AUDIT_2026-10-22.md](AUDIT_2026-10-22.md) (engines and logic). Its findings are folded in here with
the new severity scale; IDs below supersede it.

## 1. Executive summary

The engines are strong. The PLC scan, the electrical solver and project storage behave correctly: 823/823 regression
tests pass, there are no JavaScript errors in about 200 crawled button clicks, no memory leak, and the app runs at
60 fps in the Workbench. The gap to a leading professional product is in the **shell around the engines**:

1. **Two defects can take the app away from the user.** One invalid HMI setting freezes every view for good, and on a
   phone the Ladder view pushes the navigation off-screen.
2. **Undo is uneven.** Ladder and Diagram have it. Wiring and HMI do not, and one key press deletes a device with all
   its wires, then autosaves.
3. **Tablet portrait (768 px) and accessibility (WCAG 2.1 AA) are below standard.** Most of the AA failures come from
   two colour tokens and a few missing behaviours in the shared dialog and menu helpers, so they are cheap to fix.
4. **The visual system has drifted.** It uses 20 font sizes, 12 corner radii, about 154 raw colours outside the tokens,
   emoji used as icons, and browser-default blue links in places.

## 2. Scope, method, limits

**What was tested** (all scripted in headless Chromium through the real UI: clicks, typing, keys, pointer drags):

- **Regression:** `npm test`, 823 passed, 0 failed.
- **Workflows:** 10 end-to-end tasks, 50 checks.
  - New project → first rung → Verify → RUN → force.
  - Wiring from the palette, then operate and measure.
  - HMI Studio → bind → operate.
  - Save / Save as / Open / Rename / Export / Import (good and broken file) / Delete.
  - Storage full; lesson and exercise grading; Realistic connection; layouts and floating windows; keyboard-only use;
    Tagalog.
- **Electrical Diagram workflow:** library → wire → Play → Stop → Undo → ⋯ menu; right-click menus; the properties
  panel.
- **Button crawler:** every visible control in every view, and every item of every menu a control opens (441 clicks).
  It recorded errors, intercepted clicks, and controls with no visible effect.
- **Accessibility:** axe-core 4.10 (WCAG 2.0/2.1 A + AA and best practice) on 5 views × 2 themes and an open dialog;
  contrast computed per element; a Tab-order and focus-ring walk.
- **Responsive:** 6 widths (320, 390, 768, 1024, 1280, 1920) × 5 views, checking horizontal overflow, cut-off controls,
  target size, text under 11 px and work-area share, plus screenshots.
- **Performance:** cold load, frame rate and long tasks while running, a 200-rung program, and heap and DOM after 30
  cycles of every view, dialog and project switch.
- **Visual:** screenshots of every view in light and dark, the Workbench, a phone, a tablet, dialogs, menus and
  states; a CSS metrics scan.

**Limits:**

- Chromium only, emulated touch devices, headless software rendering (frame rates on real GPUs will be higher).
- No real screen reader session.
- Google Fonts were blocked, as on an offline first start.

Items marked **Suspected** need confirmation on real hardware. Everything else is **Verified**: reproduced at
runtime, or read directly from code where the code is unambiguous (marked "code").

Evidence images are in [`docs/audit/`](audit/).

## 4. What already works well (preserve)

- **Engines:** correct SLC-style instruction behaviour; a net solver that trips the nearest breaker and handles
  single-phasing, burnt coils and earth leakage; 0.01–0.15 ms per solve.
- **Data safety on load:** every imported field is checked and escaped; unknown parts are kept and written back; a
  broken file leaves the open project untouched (W4).
- **Workflows that passed end to end:**
  - First rung → Verify → RUN → force → power flow.
  - Wiring by clicking terminals; the multimeter (reads 230 V AC).
  - HMI momentary button through the hold timer.
  - Save, Save as, Open, Rename, Export, Import.
  - A failed save says "Not saved" and points to Export.
  - Lesson and exercise grading (fails with reasons, then passes after the solution).
  - Floating windows and the Workbench.
- **Keyboard focus is visible** on all 40 controls in the Tab walk.
- **Dark theme** is nearly clean for contrast (1–2 axe nodes per view).
- **Performance:** 60 fps in the Workbench while running, no long tasks, a stable heap (6.1 → 6.7 MB after 30
  cycles), and about 0.8 s to the first ladder.
