# Full audit — engines, logic, UI/UX, display (2026-10-22)

Audited commit: `6714da6` (`main`, after PR #64). Method: read every engine module (`plc.js`, `circuit.js` solver and
devices, `app.js` tick loop and project I/O, `ladder.js`, `hmi.js`, `ui.js`, `store.js`, `update.js`, `sw.js`,
`index.html` boot script) and skimmed the view modules (`workspace.js`, `schematic.js`, `freedraw.js`) for the risk
patterns found; ran `npm test`; ran headless-Chromium probes (scripted reproductions of each runtime finding below);
took screenshots of every view in light and dark mode, the Workbench layout, and a 390 px phone.

**Test suite:** 823 passed, 0 failed.

**Solver cost** (`Circuit.solve`, mean of 50 runs, per tick) is small on every example: 0.01–0.15 ms (largest:
`tank` 0.15 ms, `fwdrev` 0.13 ms, `threemotors` with 33 parts / 86 wires 0.05 ms). The 20 ms tick has a lot of headroom.

**Security of imported data:** user text (labels, comments, tag names, HMI labels, rung text) reaches `innerHTML` and
SVG through `UI.esc` everywhere checked; colours are checked with a hex pattern, HMI pictures with a `data:image`
pattern, ids with `[A-Za-z0-9_-]`. The event-log CSV export guards against spreadsheet formulas. No XSS path was found.

## High

### H1. HMI "Decimals" outside 0–100 throws every frame and stops the render loop for good
- **Where:** `js/hmi.js:380` and `js/hmi.js:228` call `toFixed(Number(o.dec) || 0)`; `HMI.clean` (`js/hmi.js:62`) keeps
  any number from −1e9 to 1e9; `frame()` in `js/app.js:1040` has no error isolation, so one exception means
  `requestAnimationFrame(frame)` is never called again.
- **Reproduced:** a Numeric Display with `dec = -1` on screen (HMI view, or any layout with the HMI). The first value
  change of its tag throws `RangeError: toFixed() digits argument must be between 0 and 100`; the frame counter then
  goes 23 → +1 → 0. Ladder power flow, Wiring animation, the status bar and the HMI all freeze, while the PLC keeps
  scanning underneath. The value is saved with the project (`buildProject` keeps `dec: -1`), so it comes back on every
  reload.
- **Action:** clamp `dec` to 0–10 in `HMI.clean` and in the property form (and `scale` to a finite number); wrap each
  view's `update()` in `frame()` in try/catch (log once, keep the loop alive). Add a test.

### H2. ▶ Play in the Electrical Diagram disables automatic tripping in the whole plant, and it stays on
- **Where:** `Circuit.setManual` is a module-level flag (`js/circuit.js:2250`, `2663`) set by the diagram's Play
  (`js/schematic.js:874`, `js/freedraw.js:997`). While it is on, `solveNet` skips short-circuit tripping, the overload
  relay / MPCB / thermal MCB `tick` never trips, and RCDs never trip — in the Wiring too, because it is the same circuit.
  Nothing turns it off when the user leaves the diagram or opens another project.
- **Reproduced:** DOL example, Play in the diagram, go to Wiring, start the motor, JAM it: overload heat reaches 100 %
  and F1 **never trips** (without Play it trips as expected). `Circuit.isManual()` is still `true` after
  `App.openNew()` of another example. A short in the Wiring then shows "with no breaker to clear it — circuit is
  dead" (`js/workspace.js:753`), which is wrong in this state. Lessons and exercises that expect a trip fail with no
  visible reason.
- **Action:** scope manual mode to the diagram: set it off when the diagram leaves the screen or Play stops, and on
  `applyProject`; or keep tripping on in the Wiring and only skip it while the diagram is the view being operated. Show
  a "Protections: manual (diagram Play)" chip in the status bar while it is on. Fix the banner text. Add tests.

## Medium

### M1. The status-bar FAULT LED is hard-wired off
`js/app.js:1249` calls `L('fault', false)`. During an I/O-configuration CPU fault the Ladder status box says
"Faulted" and a toast reports it, but the FAULT LED stays grey (reproduced on the `rack` example). **Action:** light it
from `App.status().fault`, a burnt controller, or a major module fault.

### M2. Tag storage is not visible in the data tables
`PLCcore.allocTag` (`js/plc.js:592`) gives BOOL / INT / TIMER / COUNTER tags addresses from the top of each file
(`B3:31/15`, `T4:31`, `C5:31`, `N7:31`), but the Data Files panel shows B3 words 0–7, T4 0–11, C5 0–11 and R6 0–7
(`js/ladder.js:1065–1071`). A user in a file-based project cannot see or edit the value behind a tag there (the Tags
dialog does show it). **Action:** show all 32 words (collapsed groups or a scroll), or show the used words plus a
"show all" toggle; mark words that belong to a tag with its name.

### M3. Service worker is network-first with no timeout
`sw.js:215–220` waits for the network before falling back to the cache. On a slow or flaky mobile connection (the
main audience), the installed app can take many seconds to open, though it works fully offline. **Action:**
stale-while-revalidate for the app shell (serve the cache now, update in the background, and let the updater's
"Restart to update" load the new files), or a 2–3 s network timeout before the cache.

### M4. `#import=` accepts projects from any link
The boot script in `index.html:16–52` merges projects from the URL fragment on the hosted app, with no prompt. It is
meant for the Windows/Android hand-over, but any page can link a user to
`…/aio-icms-tool/#import=…` and add projects to their list, and set the current project when none is set. The data is
sanitised by `buildProject` and existing projects are only replaced when the attacker knows a random id, so the risk is
unsolicited content, not code execution. **Action:** stage the hand-over and ask "Bring N projects from the app on
this device?" on the hosted app, or bind it to a one-time token the built-in copy writes before redirecting.

### M5. Accessibility gaps
- `#toast-root` has no `aria-live` (`index.html:178`, `js/ui.js:8`): alarms, trips and errors are not announced.
- `UI.modal` does not trap focus or return it to the opener; `UI.menu` has no arrow-key navigation (`js/ui.js:19–124`).
- The ladder cannot be navigated with the keyboard (no arrow keys between instructions or rungs), and the SVG canvases
  (ladder, wiring, diagram, HMI) expose no text alternative.
- **Action:** `role="status" aria-live="polite"` (and `assertive` for danger toasts); focus trap and restore in
  `UI.modal`; arrow keys and Esc in `UI.menu`; arrow-key selection in the ladder.

### M6. The Ladder toolbar takes about a third of its pane in split layouts
In the Workbench (1500×950) the ladder toolbar wraps to about five rows (about 250 px), leaving roughly 560 px for the
rungs. **Action:** collapse the File / Online / Address groups into one "Controller ▾" menu at narrow pane widths,
or let the palette row scroll instead of wrapping.

### M7. The Tagalog option translates only about 110 strings
`js/i18n.js:227–268`: menus, dialogs, lessons, the data table, errors and most toasts stay English. The
MutationObserver re-walks every added subtree while Tagalog is on (the status bar and views re-render often).
**Action:** decide the scope with the owner (UI chrome only, or lessons too), then extend the dictionary; limit the
observer to the chrome or translate at render time.

### M8. Documentation drift
`README.md:95` says 685 checks (now 823); `README.md:61` says 13 example projects (16, with Blank); `README.md:14` lists
`PLC-Trainer-Setup-X.Y.Z.exe`, which is not built (portable only, `RELEASING.md:8`); `README.md:49` describes the IEC
current-path and horizontal-ladder diagram views, which are now behind a developer switch
(`plc-trainer.classicViews`). `HANDOFF.md` is 68 KB, and its savepoint cells hold whole session logs.
**Action:** refresh the README counts and install table; trim the HANDOFF savepoint to the current state and move the
history into `CHANGELOG.md`.
