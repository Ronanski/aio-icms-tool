# Product audit and redesign — 2026-10-22

- **Branch:** `feature/ui-redesign`, from `main` 6714da6 plus the savepoint in PR #65.
- **Scope:** the whole web app. The Windows and Android apps package the same web code (`desktop/` and `mobile/` are thin wrappers, per `CONTRIBUTING.md`).
- **Approval gate:** nothing is merged or released. The owner merges the PR.

## 1. Method
1. **Discovery.** I read `CLAUDE.md`, `CONTRIBUTING.md` (this repo has no `PROJECT_RULES.md`), `HANDOFF.md`, `README.md` and `docs/`. I checked git state and PRs: `main` = 6714da6, and only #65 (docs) was open.
2. **Baseline.**
   - `npm test`: **823 passed, 0 failed** on `main` 6714da6.
   - CI on #64: test, web, windows and android green.
   - The earlier audit today (#63) ran a headless scan of every view, all 15 examples, every lesson and all 100 exercises (desktop, classic views, phone). It found **0 console or page errors**.
3. **Visual audit.** `scripts/shots.js` captured 38 screenshots: 7 screens × desktop / tablet / phone × light / dark. They were reviewed against professional PLC programming tools (as studied in `docs/ROCKWELL_UI_STUDY.md`) and control-room HMI practice (ISA-101: neutral surfaces, colour only for state).
4. **Measurements.** A script measured the chrome height, the position of the first rung, and page-level horizontal overflow at each size, on `main` and on the branch.
5. **Implementation.** I worked in phases and ran the full suite after each phase.

## 3. Engineering accuracy
- **No simulation, PLC engine, ladder semantics, addressing, wiring solver or HMI logic was changed.** The redesign is CSS tokens and layout rules. The only JS change is the empty-diagram message (`js/freedraw.js`, render only).
- **What verified the behaviour:** the existing 823 checks, which all still pass. They cover the instruction set (XIC/XIO/OTE/OTL/OTU, ONS/OSR/OSF, TON/TOF/RTO, CTU/CTD, compare/math/move, JSR/SBR/RET, MCR), scan order, forcing, the data table, I/O faults per target, the wiring solver, HMI tags, lessons and all 100 exercises with their solutions.
- **Not re-verified by hand this session:** individual instruction timing against a real controller. The app is a trainer. `CONTRIBUTING.md` names the SLC 500 instruction set manual as the reference, and real-hardware compatibility is not claimed.

## 5. Risks
- **Visual change for existing users:** the palette moves from warm to neutral. The owner should look at the Beta before a Stable release.
- **Toolbar on tablets:** buttons past the screen edge need a sideways swipe. The existing scroll cue fades the edge to show more is there.

## 5b. Phase 2 — functional and learning audit (every workflow)
A QA pass drove every workflow headless:
- the project lifecycle: new, open, rename, delete, export, import, reload;
- ladder editing and its error messages;
- simulation spot checks against SLC 500 behaviour;
- Learn and grading on 11 exercises;
- HMI binding, Wiring, the meter, dialogs and menus;
- edge cases: empty project, 100–500 rungs, storage full.

There were **no console or page errors**. The findings, with what was done:

| # | Sev. | Finding (confirmed by running) | Status |
|---|---|---|---|
| Q1 | **P0** | Learn's "Insert solution into ladder" replaced the **open project's** ladder, could not be undone, and was autosaved: user work lost. | **Fixed.** The solution goes into the exercise's own project (started first if needed) and Ctrl+Z undoes it. The confirm names the project. Test. |
| Q2 | **P0** | Two tabs (or the installed app plus a tab) on the same project overwrote each other silently. | **Fixed.** A save from another window pauses saving and asks "Load the other version / Keep mine". Test. |
| Q3 | **P0/P1** | The Wiring had **no undo**. Backspace or Delete removed a device and all its wires, with no way back. | **Fixed.** Undo / redo (Ctrl+Z, Ctrl+Y, ↶ ↷ buttons) for every Wiring change; live device state is not an edit. Test. |
| Q4 | **P1** | PROG → RUN did not match the SLC 500: (a) an internal seal-in came back on; (b) a latched output (OTL) was lost. Cause: the output image was cleared in both directions and there was no prescan. | **Fixed** in `plc.js`: the output image is kept (the terminals go off outside RUN), and on entering RUN a prescan resets every OTE address and every TON. OTL / OTU, RTO and counters are kept. TON, CTU, ONS and the seal-in on outputs were already correct. Test. |
| Q5 | **P1** | Cancelling the address dialog of a new instruction left `XIC I:0/0` in the rung, a hidden logic bug that Verify cannot see. | **Fixed:** an instruction whose operands were never confirmed is taken out. Test. |
| Q6 | **P1** | Every exercise Start made another saved project. | **Fixed:** one project per exercise; Start offers **Continue** or **Start over** (which replaces it). Test. |
| Q7 | P2 | "Check my work" graded whatever project was open, and passing with the inserted solution counted as done. | **Fixed:** an exercise is checked only on its own project (the message names the open one). Passing with the solution says "now try it yourself" and is not counted as done. Test. |
| Q8 | P2 | Every bad bit address gave the same "Expected a bit address…". | **Fixed:** the message names the cause — bit 0–15, a word without its bit (`N7:0/0`), a timer without its bit (`T4:0/DN`), an unknown file letter, or a name that is not a tag yet. Test. |
| Q9 | P2 | No way to find an instruction by name. | **Fixed:** "Find…" in the palette (mnemonic or words: "on delay", "compare"); Enter adds it. TON / TOF / RTO help explains Preset × Time Base. Test. |
| Q10 | P2 | Errors pane lines were plain text. | **Fixed:** an error or warning line is a link to its file and rung (click or Enter). Test. |
| Q11 | P2 | Enter in a confirm always ran the destructive action, even with Cancel focused (Reset data table, Delete). | **Fixed:** Enter presses the focused button. Destructive confirms are red and start on Cancel. Test. |
| Q12 | P2 | Imported rungs that could not be parsed were silently moved into the rung comment. A file with no project parts was accepted. | **Fixed:** opening such a project says how many rungs could not be read. Such a file is refused with a reason. Test. |
| Q13 | P3 | Escape did not close menus; no arrow keys in menus. | **Fixed** (Escape, ↑ ↓, Enter). Test. |
| Q14 | P3 | A 300-character project name widened the top bar to 2580 px. Renaming to blank silently became "Untitled". | **Fixed:** the name is cut with "…" (full name on hover); rename requires a name (max 80). |
| Q15 | P3 | The HMI empty screen said "switch to Edit", but the button is "✎ Studio". | **Fixed.** |
| Q16 | P3 | Verify was O(n²) (the pane was rewritten per line): 500 rungs took 1120 ms. | **Fixed:** one pane update per report — **206 ms**. |
| — | — | Routine names on the tag target were cut back to 10 capitals when a project was opened again (a gap in #64). | **Fixed** in `buildProject`. Test. |
| Q17 | P2 | HMI Studio has no undo. | **Fixed:** undo / redo (Ctrl+Z / Ctrl+Y, ↶ ↷) for every Studio edit. Test. |
| Q18 | P3 | Dialogs don't trap or restore focus; Delete in Open project has no undo; new objects stack at +20 px; rendering doesn't skip off-screen rungs (500 rungs: 537 ms per edit; 100 rungs is fine at 57 ms). | **Fixed:** Tab stays in the dialog and focus returns when it closes; a deleted project can be restored from the toast, and an armed "Delete?" resets after 4 s.
